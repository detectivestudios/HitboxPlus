# Hitbox+ local editor

Blockbench supplies the local 3D editor. This plugin adds editable hitbox volumes, bone/body-region
assignment, vanilla presets, GeckoLib/Bedrock import and runtime-ready JSON export. It was exercised
in Blockbench 5.2.1. No website, account, npm installation or hosted service is required.

## Install and author

1. Build from the repository root:
   `.\gradlew.bat bundleBlockbenchPlugin --offline --console=plain`.
2. In Blockbench, open **File > Plugins**, choose **Load Plugin from File**, and select
   [`dist/hitboxplus.js`](dist/hitboxplus.js). The build creates this single installable file.
3. Open **Tools > Hitbox+ > Load Built-in Hitbox Profile**, or use **Import GeckoLib /
   Bedrock Geometry** for a `.geo.json`. For another Blockbench model, open it normally and select
   **Use Current Model as Reference**. Select only the source cubes to copy if you want a subset;
   with nothing selected, all cubes are copied.
4. Use **Profile Settings** to set the target registry ID and variant. For a custom model, set the
   actual modded entity ID, for example `my_mod:mutant`, rather than its geometry file identifier.
5. Resize/move/rotate the colored boxes in the normal viewport. **Add Hitbox** creates another
   volume. **Assign Bone and Body Region** assigns selected boxes to a live bone and semantic
   region; an optional namespaced part ID distinguishes extra anatomy. Imported regions are
   inferred from names as a starting point and should be reviewed.
6. Gray source geometry remains a reference and is excluded from exports. Use **Show/Hide
   Reference Model** to inspect gaps. Native Blockbench animation/pose editing can preview the
   rig; Minecraft's procedural animations still come from the runtime provider.
7. Use **Export Hitbox+ JSON Profile**. Install the exported JSON in a mod data resource or
   server datapack as described in the [runtime guide](../../README.md#edit-and-export-hitboxes-locally).
   `/reload` activates datapack changes and synchronizes clients. F3+B shows the active volumes.

The preset list contains 90 mob/variant definitions plus four standard/slim player variants.
All vanilla living-model catalog types have live runtime providers; the
[coverage guide](../../docs/vanilla-hitbox-profiles.md) describes their behavior.
Importing a custom GeckoLib model supplies shape data;
its mod still needs a server-compatible animated bone provider before those boxes can activate.

For automatic numeric GeckoLib rigs, use [Hitbox+ Studio](../web-editor/README.md) to import
the geometry and animations, bind states, and export the rig-enabled profile. This plugin preserves
that profile's adapter metadata when importing, editing and re-exporting it. Generic source-model
adoption alone still requires a compatible provider or an explicit rig definition.

Save a `.bbmodel` while editing to retain your references, rig and hitbox metadata. **Import Hitbox+
Profile** reopens exported JSON or a Java file generated by this plugin. Arbitrary Java is
neither parsed nor executed. **Export Java Profile** is available for addon authors who prefer a
typed profile factory; JSON is sufficient for entities with a compatible registered pose provider.

## File contract

The editor and runtime share `format: "hitboxplus"`, `version: 1`. The important fields are:

| Field | Meaning |
| --- | --- |
| `entity`, `variant` | Registry ID and explicit model/visibility variant |
| `bones[].id`, `parent` | Stable bone keys and reference hierarchy |
| `bones[].pivot`, `rotation` | Parent-local reference pivot and XYZ Euler degrees |
| `volumes[].key`, `bone` | Unique editing identity and runtime bone key |
| `volumes[].region`, `part` | Common `BodyPart` name and optional namespaced identity |
| `volumes[].from`, `to` | Bone-local box limits in Minecraft model pixels |
| `volumes[].origin`, `rotation` | Optional bone-local rotation pivot and XYZ Euler degrees |

The profile stores native Minecraft coordinates: X unchanged, Y points down, 16 pixels per block.
The plugin reflects Y for Blockbench's editor and converts back on export. Rotations compose in
ZYX order, matching the runtime. Runtime providers supply current, fully composed bone transforms;
changing the JSON reference skeleton alone does not override an existing entity's animations.
Use the existing bone keys when editing a vanilla preset. Rotated boxes and zero-thickness planes
are supported. The viewport gives flat planes a tiny display thickness; the exported shape stays flat.

## Development

Gradle downloads the project's pinned Node.js runtime automatically; there are no npm dependencies.
Run from the repository root (internet access is needed for the first setup):

```powershell
.\gradlew.bat testBlockbenchPlugin bundleBlockbenchPlugin --console=plain
```

The catalog is generated from reviewed Java profiles and native model fixtures:

```powershell
# From the repository root:
.\gradlew.bat exportHitboxPlusEditorCatalog --offline --console=plain
```

The catalog is authoring data, not the built-in runtime loader. Production vanilla defaults remain
typed Java definitions. Optional user JSON profiles replace those defaults at resource reload.

`test/blockbench-smoke.cjs` also exercises the real Blockbench UI: every preset's vertices,
editing/rotation, bone/region assignment, duplicate keys, `.bbmodel` round trips, Java export,
animation mode, model adoption and GeckoLib geometry import. Start an isolated Blockbench process
with its own workspace-local `--userData` directory and `--remote-debugging-port=9233`, load this
plugin there, then run `node test/blockbench-smoke.cjs 9233`. The runner replaces its test project;
never run it against an editor containing unsaved work.
